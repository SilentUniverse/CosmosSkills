# 日常使用：工程策略与固定版本审核

普通任务在 Harness 的当前 session 里完成。Cosmos 提供 Spec、TDD、证据与人审规则，
不创建 batch、wave 或独立恢复状态。小而明确的任务不必建立 PRD/Issue。

| 请求 | 行为 |
|---|---|
| 按已接受方案实施 | 沿用授权，完成相关工程义务；未决选择只阻挡依赖项 |
| 源码跑起来边看边改 | 原生工具启动实时预览；它不承诺固定版本身份 |
| 给一个固定版本正式审核 | 固定源码与外部输入，在隔离输入上验证，展示该版本的实际产物 |
| 这个场景通过 | 原始用户决定绑定已展示的版本、范围和证据；不批准未来版本 |
| 改变既有要求 | Spec 记录受影响要求与依赖；旧候选和批准保持原身份 |
| 同任务上下文满或重开 | 使用当前 ZCode 界面提供的原生压缩或会话恢复 |
| 新任务/跨宿主继续 | Cosmos handoff 保留必要交接信息；resume 检索指定来源并核对下一步所需事实 |
| 清理目标 | Tidy 经存储所有者删除无引用且无活跃使用的可丢弃输出 |

## 交接与续接

`handoff` 和 `resume` 是保留的 Cosmos 技能，不是 ZCode 内置技能。在当前界面的技能入口
选择它们，或明确要求加载对应技能。同任务压缩后通常直接继续，无需先写交接或清空上下文。
跨任务先用原生能力读取指定旧任务；显式要求笔记，或目标环境仍有读不到的必要事实时，
写 `.scratch/<feature>/handoff.md`（无 feature 时 `.scratch/handoff.md`）。

笔记只保存剩余目标、既有授权、待决定事项、文件/证据指针、未收回的任务结果和下一步。
新任务核对相关变化后继续；不凭时间戳选目标，不重复派发尚未确认停止的工作，不重跑无关测试，
不从摘要重建人审批准。ZCode CLI 的同名会话命令与 Cosmos 技能分开；App 入口以实际可用能力为准。

## 固定候选

Git commit/tree 保存候选源码；先纳入必要的脏文件和未跟踪文件，再固定引用。
外部输入、依赖产物、构建环境单独声明。原生 checkpoint 只有覆盖这些输入时才适用。
用独立 checkout 或等价隔离输入验证，执行前后检查输入完整性；构建输出与输入分离。
审核期间无关工作可继续，批准永远指向原候选。

`workflow/evidence.py` 只固定和校验证据，不运行测试。接口见
[固定候选验证](../workflow/tdd/FULL-SUITE.md)。过程是 candidate → prepare → 原生工具执行
返回命令 → seal → review → 原始人审。先用 reuse 查询现有有效证明；每次真实尝试单独保留。
检查可以覆盖多个 Issue，完成下一张卡不重复全量测试。

## 人审

Spec 接受绑定规范化字节、accepted_digest 与锚点；交付接受另绑定 candidate、Spec、
产物、review digest、所需验证证明与原始决定。展示固定页面，显式提交才接受；
沉默、断线、空评论未提交和 Agent 填写 approve 都不是批准。

使用 `spec-review.py review-candidate ROOT REVIEW_JSON` 打开固定交付审核对象。
现有 localhost bridge 只传原始事件。原生 UI 达到同样的固定版本、字段保真、事件来源、
防陈旧/冲突提交及落盘确认能力后才替换它；不强制创建 Dynamic Workflow。

## 证据与清理

`done` 仅表示工程合同有证明；待人审、缺失手动验证与已交付分别判断。
原生任务完成不等于测试通过。失败尝试不会被新 green 覆盖；修复后只重跑受影响检查。

保留待审对象、交付版本、引用日志和证明闭包。原生存储不保证长期保留时，显式导出必要
对象并校验 hash。共享输出无法证明最后检查到删除之间无新增使用，就保留为待清理项。
工程状态查看：`workflow-state.py survey ROOT --format human`。
