# CosmosSkills：测试、注释与单 Harness 协作优化审查

审查日期：2026-09-19  
固定基线：`ee52421c3a3e5605ac08985d051ad7e83c93f8c0`（包含 PR #130）  
性质：源码、规则与 CI 配置审查；不是仓库修改、全量测试实跑或真实模型 A/B 报告。查询时该提交的 CI 返回 in_progress。未读取用户本机未提交改动。

## 结论

保留已经实施的原生宿主协作、按需文档加载、独立 Worker 入口、有界恢复与证据约束。下一轮停止扩建编排架构，优先消除验证和维护中的重复劳动。

Cosmos 定位为：**运行在原生 Harness 内的工程协作与验证策略层，附带最小的状态、所有权和证据校验工具。**

目标不是减少所有测试，而是让验证成本随独立行为与风险增长，不随 issue 数、Agent 数和重复执行次数额外膨胀。

## 一、已合理的改动，不再重做

- `DRAIN-PARALLEL.md` 已按实际后台能力允许回合结束，优先原生事件，并通过保留的 worker handle 转交用户反馈。发送不代表消费、回合结束不释放所有权。
- `WORKER.md` 已将委派执行入口与完整 TDD/调度说明分开；BATCH 文档已按执行、审阅、证明分期加载。继续检查是否存在语义重复，不再增设入口。
- `tests.md` 已要求复用现有覆盖，新增测试应保护独立错误模式；DRAIN 已要求归集时检查同波新增测试是否重复。
- schema-2 只维护兼容修复，schema-3 按需使用。普通任务不因使用 Spec/TDD 就强制生成受管批次。

这些是机制层面的合理性，不是已测量的速度或 Token 收益。

## 二、已确认的成本来源与需要验证的风险

### F1：日常 CI 为逐例计时实际强制串行

`.github/workflows/ci.yml` 的 regression 使用 `scripts/run-tests.py --durations-file ...`；`run-tests.py` 在传入该参数时强制 jobs=1。默认并行能力没有被这条 CI 路径使用。

建议将正常门禁执行与深度串行诊断分开。正常 CI 在验证资源隔离后使用受限并行及适配其执行模式的耗时记录；串行逐例分析只在调查时使用。并行所需依赖显式安装并固定。不能只移除参数就宣称优化完成。

验收：相同选中用例和断言、首次失败与 skip 分类保留；进程树、端口、文件隔离成立。对同一环境交错测量耗时，不承诺四倍提速，不把调大 timeout 当成优化。

### F2：选择器粒度粗，局部修改仍会触发完整 regression

`tests/test-policy.json` 将许多运行时和测试改动送入同一个 regression 组，CI 再在三个 OS 上执行整组。这个设计保守但不是细粒度影响分析。

建议先对真实高成本模块使用项目原生命令、test node ID 或现有组映射；对共享执行底座、配置和未知变更保持扩大检查。完整交付检查仍在约定节点执行。未经独立完整检查对照，不提高筛选精度。

### F3：测试与注释互相固化了可派生的内部结构

`tests/test_workflow_contracts.py::test_structure_maps_match_top_level_definition_order` 要求两个脚本头部注释列出的函数/类顺序等于源码定义顺序。`drain-wave.py` 因而维护一长段可由 AST/搜索恢复的函数目录（基线后 #133 已移除该断言与两份 structure map 目录）。

其他测试还匹配 Skill 中特定自然语言短语。这类检查可以在不保证行为的同时阻碍等价改写。

建议确认没有其他真实消费者后，删除手写函数目录及其顺序断言；需要导航时按需生成。保留公开命令、schema、必要模板占位符、链接与真实分发行为的检查。不能把所有文本断言一概删除，因为文档和生成文本也可能是产品契约。

### F4：重试预算的目标正确，复位与完成语义需加固

当前三次限制计的是同卡波结束的 red/blocked，不是正常 TDD 的每一次 RED。它可阻止重复派工，且仍允许其他独立可派发任务继续。

但 `retry_debts()` 在实时 dispatch contract digest 改变时复位；指南又提示 revise-or-park。契约哈希变化本身不能证明已有新诊断或获得新预算。外部环境恢复时，也不应该为了再试一次而迫使用户改变正确的需求。

建议保留累计消费与失败历史，契约修订不清空根目标消耗。重试耗尽后要求新的有效诊断/环境恢复证据或真实新增授权，不能把改写 AC 作为解锁手段。优先复用现有记录和恢复入口，不建设新事件系统。

另一个静态路径风险：park 将 ready 移为 pending；普通 `cmd_next()` 在无 ready 时返回 exit 4 并打印 batch complete，legacy overnight 将 exit 4 作为 complete。应增加一个现有入口的最小复现，验证“全部 parked/pending”只能返回未完成，不能报告交付。这不是对 schema-3 证明关闭逻辑存在同一漏洞的断言。

### F5：WORKER 精简不能漏掉 managed 执行边界

独立 WORKER 是合理减负。但 managed worker 仍须通过既有 `check-local` / continuation 协议执行，而非误走普通 pytest + close。当前 WORKER 的普通测试循环与 managed 例外应在执行前清楚分支；不要到完成阶段才加载 BATCH-PROOF 才发现职责不同。

这是需通过现有受管 worker 夹具核对的边界，不代表已观察到用户真实运行绕过预算。

## 三、TDD 的入口从“新增测试”改成“补足行为证据”

替换 TDD 主入口和 WORKER 的生成倾向，而不是在末尾再叠一条相反提醒：

> 先定位当前行为的已有测试。已有失败用例可以直接作为 RED；已有覆盖充分时验证即可，不创建等价用例。存在缺口时先扩展现有场景/参数，再新增独立用例。行为不变的重构使用相关已有回归前后验证，不为了形式制造 RED。新增测试必须保护现有测试未覆盖的独立错误模式。

此规则不允许真实缺陷缺失回归，也不允许用截图、代理自述或随意探测脚本替代必需验收。

### 持久测试按行为组织，不按任务组织

- 缺陷已由既有测试复现：复用，不创建 `fix_123` 的等价文件。
- 新输入边界：优先扩展已有参数化场景。参数化减少重复代码，不自动减少实际执行次数。
- 新契约、平台或 IO 边界：新增必要测试。
- 纯重构：复跑受影响的既有行为测试；新暴露覆盖缺口另行补足。
- 临时诊断：任务归属下保留有用证据；诊断结束按规则清理，独特的产品回归不能一并删除。

### 最低充分验证层

大量组合和纯状态判断直接测试稳定函数/模块接口；命令行、真实文件、锁、进程、Windows Job、浏览器和打包边界保留代表性的真实集成测试。不能把需要真实 OS 证明的边界 mock 成全绿。

### 运行责任

1. 每次 RED/GREEN：当前失败或直接受影响场景。
2. 模块/波次归集：相关模块和消费者，父级汇总；有有效同输入证据时不重复跑。
3. 场景/最终交付：该候选全部适用门禁。
4. 长稳/压力/全平台：按已接受的风险与交付触发，变更既有必需义务须明确批准。

同名命令、同一 Git HEAD 都不足以单独证明可复用；实际源码、测试、配置、环境与必要资源状态要符合已有有效性契约。不要为普通任务引入新缓存平台。

## 四、注释治理：删冗余来源，而不只管长度

当前 comment-gate 的 3 行/240 字符只约束单个新增块，不能防止几十个短而无用的注释；Python docstring 也不在其井号扫描规则内。

建议：

- 默认不写复述代码的注释；名字和结构能表达的直接改代码。
- 保留接口前置条件、单位/坐标/所有权、并发与生命周期、不直观的兼容原因和可核实的 workaround 退出条件。
- 不复制 issue 经过、Agent 推理、测试结果或可机械生成的函数清单到源码。
- 在已有 diff review 内检查注释的独特贡献，不创建专门注释审查 Agent，不扫全仓制造修改。
- 3 行/240 字符门建议单独改为审查提示或项目显式选择的格式门；这是风格契约变化，应独立确认和提交。保留必要许可证/生成说明。

不建设全语言注释解析器，也不将注释比例换成另一项硬指标。

## 五、层次定义与单 Harness 接入

### 原生 Harness

模型、会话、上下文压缩、工具、原生子 Agent、消息/等待/停止、浏览器、权限 UI。

### Cosmos

目标和接受标准、当前任务归属、工程依赖/资源边界、验证选择和证据、必要恢复、简短工程进度与最终汇总。

### 项目工具链

构建、测试框架、项目 fixture、设备驱动、已有 CI。

不重建 Scheduler + Session Runtime + Memory DB。用户仍然使用 Spec → TDD -p → 聊天反馈 → 进度 → 最终汇总。

### Oh My Pi（OMP）

本文将 ON-PI 解释为 OMP。先做原生 Skill 装载，不写外部 runner：

- 使用实际可发现的平铺 skill 目录，确保共享脚本与文档引用可达；不要仅复制 SKILL.md。
- 启用 skill commands 时，原生形式是 /skill:spec 与 /skill:tdd（wave 模式）。
- 复用原生 task、Agent Hub 和 steering。完成输出不直接当成 Cosmos 验收证明。
- 核对其 `skill://` 路径边界、同名 skill 优先级和隔离 worktree 与当前波的源码身份。不能假设所有 ../ 引用或跨工作区状态自动成立。
- 不并列启动另一套长程规划循环和逐回合审查器；是否增加审查以实际风险为依据。

### Codex

使用现有 `.agents/skills` 与项目 AGENTS.md 引导，通过 `$spec`、`$tdd -p` 或技能选择器进入；复用原生子 Agent 和后续指令。不套用 Claude CLI 的 flag/进程模型，不把 hooks 改成中性名字当作已适配成功。

先验证一个真实宿主；第二个宿主产生真实差异后才抽取最薄的公共衔接。原生 UI/子 Agent 运行信息归宿主管，工程完成与证据归 Cosmos 管。

## 六、建议的实施顺序

### PR-A：清理会制造负产物的规则与测试

修改 `tdd/SKILL.md`、`tdd/WORKER.md`、`tdd/tests.md` 使复用优先一致；核对 managed worker 执行入口（无消费者的函数目录及顺序断言已随 #133 移除）。注释硬门降级单独授权，不与行为修复混在一起。

验收：已有失败测试能完成修复且没有等价新测试；行为不变重构不会为制造 RED 改断言；改变公开契约仍能被对应检查阻止。

### PR-B：修正重试与收尾风险

在现有 drain/overnight 测试里扩展失败/恢复/park 用例。禁止“无 ready = 交付”；失败预算不能通过无意义契约变化清空，已恢复环境可在有效授权内继续。

验收：全部 pending 返回未完成；预算耗尽保留历史；真正独立工作仍可推进；真实运行状态未知时不重复执行。

### PR-C：降低验证执行成本

先读现有回执，对最贵的模块和重复命令开展一次定向治理；正常 CI 不为常态计时强制串行。沿用原生命令/现有选择器，不引入新测试平台。保持资源隔离和相同检测能力。

验收：比较同一任务最终候选下的检查范围、完整时间、重复运行、启动/fixture 成本与失败。不能只比较文件数、用例数或某次单测时间。

### PR-D：OMP/Codex 最小原生装载验收

不新增多宿主控制器。用已有 fixture 在目标 Windows Harness 中执行：两个不冲突任务并行、一张 UI 卡浏览器复验、一次中途纠偏、一次查看工程进度、最终汇总。

源码里已有反例优先复用；同一反例复用不同入口时参数化，不为每种标签复制整套测试。

## 七、衡量方式

优先保持相同需求、隐藏验收和高风险不变量，再比较达到已验证交付的时间与全部实际成本。

读取已有 receipt 与宿主 usage；统计同候选重复检查、全量/构建次数、fixture/启动成本、无关结构修改造成的测试失败、人工接续次数。缺失 usage 留未知。

默认不启动付费模型评测，不用速度目标减少必需断言，不通过调整基线吞掉回退。一次成功 smoke 只证明该路径能跑，不代表普遍收益。
