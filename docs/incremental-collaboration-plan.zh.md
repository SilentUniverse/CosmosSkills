# 增量协作：职责与工程事实

Cosmos 是工程策略层。原生 Harness 独占 Agent、task/session、并行、调度、重试、
持久化、恢复、上下文、工具和 UI。当前使用见[日常说明](checkpoint-local-release.zh.md)，
字段见[工件合同](../workflow/ARTIFACT-FORMAT.md)。

| 工程事实 | 权威 |
|---|---|
| 目标、范围、依赖、待决定事项 | Spec / Issue 合同 |
| 哪条 AC 得到什么证明 | 不可变检查证据及映射 |
| 用户批准了哪个对象 | 固定 Spec/candidate 对应的原始人审记录 |
| 正在运行什么、是否停止、如何恢复会话 | Harness 当前原生状态；持久历史不能证明进程存活 |
| 续接时缺少的未完成工程事实 | 原生历史 / 原工程工件；必要时由 Cosmos handoff 笔记补充 |

Spec 按锚点依赖判断受影响范围；TDD 用相关检查证明行为；Tidy 汇总未决义务并按存储
所有者的安全删除能力清理。没有新总状态文件、执行阶段、global wave 或 repair 队列。

一个固定候选可承载多个 Issue，一个检查可覆盖多个 AC。正式人审对象先固定，批准不跟随
workspace。新候选不继承旧批准；旧候选等待人审时，无关开发和验证可继续。

并行必须有真实写入隔离和资源健康保证。共享目录写冲突就串行，独立 checkout 通过支持 cwd
的原生入口执行；设备、数据库和端口的互斥由项目 fixture/服务/CI 承接。Cosmos 不再造锁服务。

测试按行为、模块/集成、固定交付候选选择。重复失败保留事实；无新证据不反复全量。
只有独立且需持久追踪的工程缺口才建 Repair Issue。性能用同口径时间和足量样本判断；
静态检查、模型 token 和删除代码行数不能证明质量或速度收益。
