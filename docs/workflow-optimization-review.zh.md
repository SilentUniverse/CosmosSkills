# 工作流优化：九定律审查、实现边界与消融证据

结论：采纳文章对自主执行、持久记录、上下文加载的职责划分。运行层采用原生会话、按需输入和确定性状态脚本；共享工作树保留完整收波屏障。质量与正确性优先，其次是完整交付耗时，再其次是上下文与 token 成本。现有证据支持这些局部选择，尚不能证明真实人机协作的全局最优。

审查依据是[工作流文章](agent-workflow-proposal.zh.md)、[九条设计定律](../claude/design-principles.md)和仓库实现。Git 基线和源码版本由下方原始报告记录。Spec 的用户审阅检查点继续生效：`ready` 表示技术就绪，不能代替接受方案。[原聊天分享](https://chatgpt.com/share/6aa0642a-b508-83ea-8f6b-c73e014ba001)的公共抓取只返回标题，未取得的聊天正文不作为证据。

| 定律 | 审查结论与实现选择 | 反证或验收边界 |
| --- | --- | --- |
| First Principles | 以用户目标、约束、授权和证明路线决定执行；文件数量不决定是否建 issue | 队列清空不等于用户目标完成 |
| Invariant | 执行身份、行为合同、验证配置和写入归属必须一致；先确认 worker 及受管子进程终止，再收波 | 旧 execution、配置漂移、越界测试、未收集执行均不得默认为成功 |
| Parsimony | 共享事实一份，投影按需生成；复用原生会话、已有 ledger 和基线，不引入常驻知识服务或新的缓存层 | 单 worker 的共享 JSON 并不更小；因此串行入口直接取 packet |
| Locality | 并行 brief、冲突配对和并行规则只由需要它们的入口消费；归属差分只在收尾计算 | 串行调度必须保持零次冲突配对；不得为了加速并行而常驻加载其材料 |
| Provability | 状态写入经过同一 OS 锁；多文件变更先准备完整，再通过临时 journal 发布；handoff 按版本消费 | 锁文件年龄不证明失去所有权；部分发布、并发备注与旧 handoff 均有拒绝或恢复路径 |
| Adversarial Review | 用独立只读审查和具体反例攻击合同、调度、归属、进程与恢复边界 | 包括保留旧批次 ledger、删除最后一张 live 卡、大小写目录被整体删除等反例 |
| Empiricism | 保存配对样本、环境、源码摘要；区分耗时、字节、正确性与模型指标 | 字节减少不能证明 token、缓存、人工注意力或模型质量改善 |
| Reversibility | 原生会话 ID 只在运行进程中持有；共享投影不落盘；journal 发布后清除；保留兼容读取路径 | 多个无身份的 legacy 执行不能推断为一个批次；身份不明时拒绝自动接管 |
| Evolution | 先实现可靠执行与无重复输入，再以实测决定隔离调度和模型层优化 | 共享树的滚动补位必须等待隔离、采纳和重新验证协议成立 |

文章中三个关键建议与落地结果如下。它们的运行规则分别由链接的文件维护，本报告不成为第二份执行策略。

1. 原句：“能否自主执行、是否需要持久记录、需要加载哪些上下文，是三个独立判断。”处置：采纳。[共享策略](../claude/CLAUDE.md)、[Spec](../workflow/spec/SKILL.md)和[TDD](../workflow/tdd/SKILL.md)允许约定明确的工作直接执行；排队、分派、依赖或合同历史确有消费者时才需要卡片。入口仍检查相关产品状态和活动分派，查不到同名卡不能证明功能不存在。知识留存独立于 issue 完成，只保存能改变后续判断、具有证据和检索入口的约束。
2. 原句：“批次基线区分历史测试与本批贡献。”处置：采纳并限制承诺。[归属审计](../workflow/tdd/scripts/drain-wave.py)利用已有基线，检查准入范围内新增、修改和删除的测试。Git 的原有 dirty/untracked 内容不算本批贡献；没有 Git 时比较已捕获范围的文件身份。执行收尾审计的调用方用 `audit --execution <id>` 明确本批成员，可重复该参数；runner 自动提供自己派发的 IDs。保留的旧 ledger、未分派历史卡、缺失卡片和路径歧义不能替新修改背书。该审计仍不代替全部代码变更的归属核对和集成验证。
3. 原句：“一份可用的 handoff 应当让没有会话历史的执行者恢复以下判断”。处置：采纳其剩余目标、授权、代码关系、证据与下一步要求。[handoff](../workflow/handoff/SKILL.md)和[resume](../workflow/resume/SKILL.md)使用带版本的发布与消费，多个候选明确报歧义；源工作区漂移不能被重新盖章掩盖。原生连续会话保留已有理解，真实上下文边界才建立恢复桥。

运行实现集中在[状态事务](../workflow/workflow_runtime.py)、[状态投影](../workflow/workflow-state.py)、[受管进程树](../workflow/process_tree.py)和[外部 runner](../scripts/overnight.py)。直接 issue 执行用 `start` 一次得到 packet、execution 和基线引用；并行用一次 `briefs --compact` 得到完整输入投影。确定性的共享预检由脚本运行。进程恢复覆盖 POSIX process group 和 Windows Job，不代表能够终止脱离宿主的远程任务。journal 支持进程中断恢复，不宣称断电持久性或任意非协作编辑器之间的完整事务隔离。

**确定性消融数据。** [原始报告](benchmarks/workflow-ablation.json)是数值与样本的权威来源，保留源码 SHA-256、Git 基线、平台、Python 版本和所有原始计时。复现命令：

```text
python3 scripts/benchmark-workflow.py --samples 31 --output .scratch/tmp/workflow-ablation.json
```

Windows 使用已安装的 `python` 或 `py -3` 启动同一脚本。计时环境为 macOS 26.6.2 arm64、Python 3.9.6；测试进程结束后单独运行基准。每项预热 3 次、31 对交替顺序样本，以固定种子的配对中位差 bootstrap 给出 95% 区间。耗时不包含 CLI 启动和模型请求，区间只描述本次本机样本，不能推广为跨机器保证。对照是当前代码中关闭一个机制的消融，不是整个 Git 基线版本与候选版的端到端对比。

| --- | ---: | ---: | ---: | ---: |
| 4 | 0.427 | 2.146 | 0 / 6 | 1.716–1.726 |
| 64 | 4.293 | 6.037 | 0 / 6 | 1.729–1.776 |
| 256 | 16.764 | 18.573 | 0 / 6 | 1.779–1.859 |

并行容量上限是 4，所以这里的配对次数为 6，并不随总 ready 数继续增长。结论是串行无须承担这项工作；毫秒级差值不足以证明 AI 任务端到端明显加速，也不支持为此新建持久调度缓存。零配对不等于总流程零新增成本：执行身份、基线和事务保护有共享的正确性成本。完整串行任务的性能非劣仍须在后续任务试跑中验证，不能由该表代替。

4 worker、32 历史卡时，控制器输入投影减少 68.8%；单 worker 增加 17 字节，2 worker 无历史时增加 5 字节。保持一个并行 schema 比增加自适应变体更简单，串行正常路径使用 packet，不消费这份并行包装。独立 worker 仍需得到下一步必需的共享原文：JSON 指针不会自动提供跨 agent 内存。这些数值不是所有 agent 合计的 API 输入，更不是 token 或缓存命中率。

| 被消融的机制 | 保留机制的观察 | 移除机制的观察 | 决策 |
| --- | --- | --- | --- |
| 共享快照锁 | 写锁持有时拒绝并发读取 | 读取能穿过写入区间 | 保留，不能用省一次锁换一致性 |
| 首次读取版本校验 | 并发追加的备注被保留，过期写入拒绝 | 并发备注丢失 | 保留 |

| 脚本预检 | [mock runner 回归](../tests/test_overnight.py)只有实施与收尾 2 次模型启动边界 | 增加一轮准备时，反事实推算为 3 次；原始报告没有执行该项消融 | 机械准备交给脚本；实际模型时延未测 |

确定性验收为 327 个测试通过；技能目录校验、driver selftest、差异空白检查通过。常驻共享策略为 7,701/8,000 字节，28 项发现描述共 6,647/12,000 字节。[CI](../.github/workflows/ci.yml)覆盖 Linux 全量检查及 macOS/Windows 关键运行路径；此次实际执行平台只有 macOS。安装脚本的隔离目标导入检查通过，没有据此声称已经在 Windows/Linux 本机运行全部测试。

**原生前缀与 GLM。** 相同指令、工具定义和共享输入保持稳定顺序；连续轮次追加新内容，由宿主重放原始消息及工具块，不为了缓存造预热请求或重写历史。缓存输入仍占上下文。[OpenAI 官方缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)要求相同前缀，不能从相似文意推断命中。

GLM 的隐式缓存自动工作，可通过 `usage.prompt_tokens_details.cached_tokens` 观察；其文档中的 token 折扣不适用于 Coding Plan。不能假定未公布的统一 TTL、最小前缀或跨 agent 共享保证。[GLM 缓存说明](https://docs.bigmodel.cn/cn/guide/capabilities/cache)

GLM preserved thinking 在 Coding Plan 默认开启、标准 API 默认关闭；标准 API 启用时使用 `thinking.clear_thinking: false` 并按原顺序完整回传 `reasoning_content`。由适配器重放，项目文件不保存推理正文。[GLM thinking 说明](https://docs.bigmodel.cn/cn/guide/capabilities/thinking-mode) 操作细节集中在[适配器指引](../workflow/tdd/SESSION-REUSE.md)，不进入每轮常驻上下文。

**下一步以收益门槛推进。** 下面是待实施或待实测的切片，不是对现有保证的扩大。

| 次序 | 下一步与最小输入输出 | 接受条件 | 不接受的捷径 |
| --- | --- | --- | --- |
| 1 | 明确无 issue 执行的准入接口：输入目标、准入路径/资源和现有权威指针；输出 execution 与基线引用；只有需要协作时才持久化归属 | 与 issue 共用状态锁、漂移拒绝和归属检查；已有 ready 卡直接复用；单执行者无协作时不建空卡 | 当前 `survey` 加协调规则属于策略约束，不能冒称对无卡工作已有完整机械强制 |
| 2 | 在用户给定 provider、端点和预算后，做完整任务的配对试跑：先 4 类任务 × 2 版本 × 2 provider，共 16 次任务尝试；必要时按方差扩展 | 相同代码/验收起点，随机交替顺序；独立验收，不让执行者给自己评分；所有 agent 的耗时与 usage 一并统计 | 不能把本报告的 legacy 合成卡当成现代合同或模型质量评估 |
| 3 | 用既有代码地图的局部入口验证知识留存：记录难恢复约束及其证据，下一次相关任务按指针读取 | 观察重复探索、检索错过、错误复发和过期知识；无合格知识则零新增条目 | 自动每轮写摘要、复制源码和为一条知识先整理全库 |
| 4 | 仅当波次尾部等待成为已测瓶颈，试验隔离 worktree 中的事件驱动补位；每项结果经受控采纳与集成验证 | 净关键路径收益覆盖启动、采纳、冲突和额外验证成本；串行入口仍不创建隔离状态或加载并行材料 | 在共享工作树中直接解除全局收波屏障 |

补位的消融思考可以用一个明确的上界例子说明。8 项独立任务耗时为 `[8,1,1,1,1,1,1,1]`，有 4 个槽位，忽略协调开销时，固定两波需要 9 秒，滚动补位需要 8 秒，最多节省 1 秒。若隔离与采纳在关键路径上增加超过 1 秒，利用率提高仍会让交付更慢。这是算术模型，不是当前运行器的实测；它说明应测最终交付时间，而不能把“槽位一直忙”当作最优目标。

模型试跑按完整目标统计：独立验收通过率、错误成功报告、遗漏要求、回归与返工；在质量门槛满足后，再比较总耗时 p50/p95、关键路径等待、全部 agent 的重复调用与冲突次数；最后比较实际输入、缓存命中输入、未缓存输入、输出及可取得的上下文峰值。人工侧记录需要新决定的次数、重复确认次数和主动处理时间，不把人不在线的等待混入主动处理成本。缓存率使用 provider 实际 usage 的加权计数，不能平均各轮百分比；首次调用也不能未经观测就标为冷缓存。Coding Plan 与标准 API 分开报告。

本报告包含的真实模型任务对照、GLM 缓存观测、人工主动时间样本数均为 0，未包含真实模型请求。模型试跑以用户给定 provider、可用端点和调用预算为前提。原始报告的哈希支持复现确定性结果；缓存、质量和人机端到端收益保留为待验证命题。
