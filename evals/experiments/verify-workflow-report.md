# Verify 工作流验收 — 2026-09-16

## 决策与使用方式

保留 Cosmos 的 `verify` 构建正文，把改进放在整个工作流的衔接上。对照仅替换
Pstack 的 `create-verification-skill` 创建过程，没有引入 Pstack 的其他 skill。
本次结果不支持为了性能或质量收益而替换正文，也不能证明自有实现普遍更好。
工作流方向参考[用户提供的讨论](https://chatgpt.com/share/6aa9a6db-e8f4-83ea-ac71-41fc39cb2074)：
把可复用的操作与观察能力留在项目内，由下一位执行者直接运行。

| 当前情况 | 工作流 |
|---|---|
| 现有测试、CLI/API 或驱动能操作并观察目标 | 直接 SPEC/TDD；缺测试、缺断言或业务失败属于普通 RED。 |
| 无法启动、操作或观察所需路径 | `/verify <场景>` 补足这一能力，实际运行后返回原任务。 |
| 产品变更影响已有驱动或操作说明 | 在同一 TDD 切片内维护，复用本轮匹配的检查结果。 |
| 工具漂移需要调查 | `/verify -maintain <范围>`，修复并重放受影响路径。 |
| 排障缺少控制或观察工具 | DIAGNOSE 补足能力后回到原始症状，继续复现与修复。 |
| 下一位执行者接手 | 从项目已有 agent 入口找到项目内工具，直接使用。 |

Verify 的交付物是应用仓库里的可运行工具和操作知识。它复用已有测试、运行标识、资源所有权、
证据位置及结果消费者，不产生第二套队列或完成状态。地图按需创建；清理只处理本次拥有的资源，
历史证据遵循原有保留策略。接口改名本身不构成删除旧证据或询问用户是否删除的理由。

入口及具体约束见 [Verify](../../tooling/verify/SKILL.md) 和
[工作流说明](../../workflow/README.md#application-verification-loop)。

## Pstack 创建过程对照

上游固定为
[create-verification-skill @ c1c0a328](https://github.com/cursor/plugins/tree/c1c0a32802223f4be824112dd83d33ad29a8b26c/pstack/skills/create-verification-skill)。
两组共享 Cosmos 的入口、维护分支和调用方约束，只改变创建正文；第三组提供相同任务要求但
不提供 Verify 元技能。未采用的候选源码已清理，固定上游链接和测量摘要保留。

### 固定环境

- macOS arm64、Python 标准库、各次独立 Git 项目；业务夹具是实际子进程 CLI。
- Claude Code 2.1.236，配置的主模型为 GLM 5.3 Flash [1m]、medium；原生遥测另含 GLM 5.3。
  这不是 GPT/Codex 原生执行评测。
- Read/Write/Edit/Bash/Glob/Grep；限制 shell 命令、不绕过权限。没有网络工具；shell 网络限制
  由实验指令约束，不是操作系统沙箱。模型随机种子不可设，固定输入及执行顺序，保留跨次波动。
- 每阶段最多 300 秒及 CLI 估算 $0.8；创建→维护→冷使用案例总上限 900 秒、600,000
  原生累计 token、180 次工具调用。累计 token 包含缓存重读，不等同付费 token。

### 实际结果

| 方法 | 普通修改 | 创建→维护→冷使用 |
|---|---:|---:|
| Cosmos 创建正文 | 3/3 通过 | 3/3 完成，独立 IO 检查通过 |
| 轻改 Pstack 创建正文 | 3/3 通过 | 2/3 完成并通过；另一次创建阶段超时 |
| 不提供 Verify 元技能 | 3/3 通过 | 3/3 完成，独立 IO 检查通过 |

9 次普通修改均未加载 Verify 正文、生成验证包或建立工作队列。这支持当前夹具上的按需调用，
不证明所有宿主和任务都没有额外成本。

8 个完成的能力循环均通过独立的正常运行与错误注入检查：实际 add→complete/finish→list
调用、故意不保存完成状态时失败、保留观察证据、释放自有状态、保留外部状态；维护后由新的
模型上下文发现并运行工具，未改写工具来迎合结果。

## 整体工作流验收

另外使用已验证的项目工具，要求普通 TDD 将 CLI 的 `complete` 改为 `finish`，拒绝旧命令，
保留 add/list 及完成持久化行为。该场景检查产品修改、既有驱动维护和交付证据之间的衔接，
不再比较创建正文。

前两次运行完成业务修改和回归，但未加载 TDD skill，并把旧证据当作必须刷新或删除的对象，
产生不必要的交付询问。补充保留语义后，第二次仍未加载该规则，不能据此声称规则已修复行为。
实验入口随后明确调用并检查 TDD 文件加载。一次以 `/tdd` 开头的 CLI 输入被宿主解释成未知
命令，0 次模型调用，记录为入口失败；最终改为普通文本显式调用。

显式调用 TDD 的最终运行实际加载了该 skill，先得到业务 RED，再修改产品，随后维护并重放既有
驱动。独立检查确认新命令、旧命令拒绝、未知 ID、状态保留和错误注入均符合要求；产品 3 项及
驱动 2 项测试通过，没有加载 BUILD 或创建 issue 队列。外层用时 298.664 秒，累计 504,225
token，超过 350,000 上限；这次不是预算内成功，也不是省 token 的证据。

补充的历史证据检查发现：该运行复用了 `evidence/replay`，覆盖了部分旧观察。它没有再次向用户
询问清理，但保留语义仍失败。原始失败保留，未把业务绿色当作完整交付成功。

对已生成工具加写入前的非空目录拒绝保护，并修正本地操作说明后：

- 同一真实调用的 RED→GREEN：重复目标从静默覆盖变为拒绝，已有文件逐字节保持不变。
- 正常业务路径、错误注入、资源清理及外部状态保留继续通过。
- 新的冷执行者只读项目入口和本地说明，使用新证据目录成功运行；13 次工具调用、外层
  38.405 秒，已有文件全部未变。它没有再次生成工具或运行不相关的工具单测。

该保护已进入 BUILD 的生成契约，并新增[永久回归案例](../cases/verify-evidence-retention.json)
及真实 IO grader 测试。工具修复由本次实现直接完成，冷执行验证复用；不能把它说成新生成规则
已经通过多轮模型统计验证。主流程的编排已连接，宿主自动发现和复杂应用覆盖仍有下述边界。

## 九定律落点

| 原则 | 本次约束 |
|---|---|
| 第一性原理 | 解决无法操作或观察的能力缺口，先判断现有工具是否足够。 |
| 不变量 | 实际用户路径、独立业务期待、已有证据及外部状态不能被便利操作破坏。 |
| 简约 | 一个 Verify 入口，两个按需分支；没有新队列、常驻脚本或强制全应用地图。 |
| 局部性 | 应用知识留在应用仓库；接口、驱动和说明在同一修改中更新。 |
| 可证明性 | 独立进程观察与错误注入，检查工具确实能发现错误。 |
| 对抗审查 | 检查伪成功、错误目标、状态污染、证据清理和冷执行可用性。 |
| 实证 | 失败、超时和预算超限纳入结果；结构检查不当作质量或速度收益。 |
| 可逆 | 候选没有收益证据就不替换生产正文；资源隔离，不增加默认调度。 |
| 演化 | 从一个代表场景形成闭环，有真实消费者后再扩展地图与平台能力。 |

## 成本、验证与局限

Verify discovery description 从初稿的 274 缩到 209 UTF-8 字节；全部 description 为
7,121/12,000 字节。共享 `claude/CLAUDE.md` 保持 7,495/8,000 字节不变。
调用方只新增条件分支，正文和地图按需加载。
没有新增自动评测、定时任务、全局 hook 或每任务完整维护要求；不声称额外 token 为零。

SPEC/TDD 两份主文件的新增说明从 113 个英文词缩至 41 个，两个引用文件的 124 个新增词全部
删除，复用已有就绪、RED/GREEN 和结果复用规则。词数按空白分隔统计，不是模型 token 实测。
此次去重通过结构校验与独立语义冷读；上述模型实验对应精简前文本，没有为此次去重新跑模型。

最终确定性全套运行 450 项，447 通过、3 项 Windows 专属检查跳过，外层用时 88.191 秒。
30 个 skill、20 个 eval case 及真实 IO grader 回归通过。安装器覆盖源目录及已安装技能的链接
读取；完整结果保留在测试回执中。

这次覆盖 CLI subprocess 及仓库内技能文件加载，没有验证浏览器、Android、共享设备、打包后
UI、SPEC 管理批次的真实结果适配器或 Codex 原生自动发现行为。上述连接有契约和确定性检查，
尚不能称为全部平台端到端验证。下一次应在实际产品需求首次遇到相应能力缺口时，按同一闭环
补一个代表场景，而不是提前建立全平台验证框架。

## 最终 ATK / LINT

ATK 对常规路径成本、路由、执行证据和报告口径作独立只读审查：常规 TDD 没有强制 BUILD、
全图维护或额外审批；修正一处预算报告遗漏，完整列入 Cosmos 和无 Verify 组的超预算运行。
LINT 探针及语义冷读未发现实际泄漏；最终闭环的原始失败和修复证据保留。

结果口径排除了隔离目录错误和预算过低的试跑，并校正 scope grader 对自有临时目录只读检查
的误报。18 次正式尝试中有 17 次完整终态遥测，超时尝试也保留在结果摘要中。
