# Verify — maintain project capabilities

Loaded for an existing verification package whose operations or feature knowledge need checking.
Use the named area or the current change's affected scenarios. An explicit whole-package audit
covers every mapped feature; otherwise report the bounded scope. Resolve ambiguous targets from
the task and repository before asking the user.

## Inspect and classify

Read the selected feature entries, their driver and test pointers, and related source changes.
Reconcile the feature index with its files. Check new or removed public entry points in the selected
area; require a concrete source path before adding an entry. Changes to a shared driver expand the
runtime pass to its affected consumers.

| Finding | Action |
|---|---|
| Operating knowledge is stale | Correct the affected entry from source and observed operation. |
| Product behavior works but the driver cannot exercise it | Repair the driver and replay the affected paths. |
| Environment, target or access is wrong | Restore declared setup within existing authority; otherwise report the missing condition. |
| Product violates an accepted requirement | Preserve the failure and return to the caller's repair workflow. Maintenance alone does not authorize product changes. |
| Requested behavior changes the requirement | Route that change through `/spec`; retain the original expectation until revised. |

Do not resolve a product regression by changing map expectations, weakening assertions or hiding
failed attempts. Routine maintenance edits its own instructions, helpers and corresponding tool
tests; broader product repair continues only under the caller's existing authorization.

## Run the affected paths

Source inspection does not replace runtime evidence. Merge compatible recipes to avoid repeating
setup, while retaining required initial states and covering each selected feature. Drive shared
instances under one owner. Use a fresh isolated invocation when the application's execution model
requires it; parallel source work does not authorize concurrent device control.

Apply the parent skill's capability proof to the maintained assets. After an unexpected result,
recheck target health and inspect the failing state before choosing an explicit recovery. Replay
every repaired driver path and every corrected recipe. Preserve evidence and clean failed-attempt
residue as well as the final successful run.

Record covered paths, omitted paths, unreachable prerequisites and their attempted operations in
the existing run evidence. A partial or unreachable path is not a pass. Report either no corrections,
verified corrections, or the remaining gaps, with the actual coverage. Schedule nothing by default;
when periodic maintenance is requested, choose its scope and cadence from drift risk and run cost.
